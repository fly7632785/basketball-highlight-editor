# v2.9.2 验证记录

## 本轮改动

- 修复篮筐附近一帧漏检后，主轨迹被其他篮球抢占导致的漏候选。
- 恢复轨迹只沿着“篮筐后续走廊”追踪，不再用窗口内所有篮球判断侧向离开。
- 后续篮筐走廊判定纳入球体半径，避免球心略偏但球体已经穿过篮筐时被拒绝。
- 保留原有硬过滤：穿框前明显侧向偏离、明确反弹、可靠的网内无运动证据仍不进入审核队列。

## 回放结果

测试数据：1 小时视频的 119 个原始精筛窗口，使用已有检测缓存回放规则。

| 指标 | v2.9.2 |
|---|---:|
| 原始窗口 | 119 |
| 产生 refined 事件 | 48 |
| 按 2 秒去重后审核候选 | 46 |
| 参考进球时间 | 18 |
| 候选命中 | 16 |
| 候选 Precision | 34.8% |
| 候选 Recall | 88.9% |
| 候选 F1 | 50.0% |

这里的标注只覆盖原始候选集，不是整段视频逐秒标注，因此不能宣称为全视频准确率。

本轮恢复了：`466.55s`、`965.55s`、`2882.23s`。仍未恢复：`444.48s`、`2960.69s`；这两个窗口当前仍没有形成可验证的完整穿框轨迹，暂不通过猜测放宽为自动进球。

## 性能与验证

- 已有缓存下 119 个窗口规则回放约 `2.1s`；这不是首次 YOLO 推理耗时。
- Python 测试：`158 passed`。
- 本轮只改变候选恢复与后续走廊判定，没有把音频单特征接入自动进球门槛。

## 结论

v2.9.2 的收益集中在**遮挡/轨迹切换造成的召回损失**，不等于解决单目视角下的擦框、边缘入框和球心漂移歧义。下一轮应继续用新增视频验证，避免在这两个窗口上做针对性硬编码。
