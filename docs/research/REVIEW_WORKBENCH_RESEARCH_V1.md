# 审核工作台开源方案调研与 V1.5 建议

> 调研目标：比较现有篮球识别工程、开源标注/质检工具、开源视频剪辑工具在“候选片段审核”上的设计，确定可直接吸收且适合本地桌面应用的方案。

## 结论

**不建议把 CVAT、Label Studio、FiftyOne 或 Kdenlive 直接嵌入产品。**它们要么是完整标注平台，要么是专业非线性编辑器，部署和交互复杂度都明显超出当前单视频、单人审核的 V1 范围。

最合适的产品形态是：

> **AI 生成候选 → 按优先级进入审核队列 → 视频/时间轴/证据并排复核 → 确认、排除或暂缓 → 批量导出，并沉淀为算法训练样本。**

核心组合：

- **CVAT**：吸收审核状态、问题标记、进度和质量控制思想。
- **Label Studio**：吸收“模型预标注 + 人工最终结果”的数据模型。
- **FiftyOne**：吸收筛选、排序、低置信度和错误样本视图。
- **LosslessCut**：吸收时间轴、区间编辑、逐帧/关键帧跳转、快捷键和撤销。
- **篮球开源工程**：继续复用候选生成、前后置片段、轨迹/篮网/音频证据，不把它们当作审核 UI 依赖。

## 当前实现与参考方案差异

### 已经具备的能力

当前代码已经覆盖了审核闭环的骨架：

- 单视频候选队列和视频预览。
- `pending / goal / excluded` 三种审核结果。
- 进球、排除、上一条/下一条、自动跳下一条。
- `Enter` 确认、`Backspace` 排除、方向键切换、撤销。
- 备注、片段开始/结束时间修改、重新分析。
- 候选默认片段和审核后片段均已持久化。
- 视频 `duration_ms`、分辨率、FPS、编码信息已进入项目数据。
- 检测结果已保存到 `evidence_json`，可以作为后续证据面板和训练数据来源。

### 主要差距

| 能力 | 当前实现 | 优质方案 | 差距判断 |
|---|---|---|---|
| 审核状态 | 只有 `pending / goal / excluded` | 状态 + 原因 + 是否需要二次复核 | **P0** |
| 模型与人工结果 | 模型字段在候选中，证据主要藏在 `evidence_json` | 模型结论、置信度、人工结果并排显示 | **P0** |
| 队列顺序 | 按 `event_time_ms` 时间顺序 | 低置信度、证据冲突、疑似误报优先 | **P0** |
| 筛选 | 主要按审核状态 | 状态、置信度、原因、证据冲突、时间范围组合筛选 | **P0** |
| 证据 | 主要看视频 | 球轨迹、篮网运动、音频、几何穿越、预测落点 | **P0** |
| 时间编辑 | `mm:ss` 输入框 + 普通播放条 | 可拖动区间、事件点、逐帧、循环预览、缩放 | **P1** |
| 批量操作 | 暂无完整批量审核 | 批量排除、批量确认、批量改原因、按筛选导出 | **P1** |
| 历史 | 当前保存最新审核状态 | 每次操作历史、撤销、审核耗时 | **P1** |
| 质量统计 | 已有审核概览和 Engine 统计接口 | 审核进度、确认率、误报类型、平均审核耗时 | **已完成 V1** |
| 算法闭环 | 已支持 JSONL/CSV 导出人工审核结果 | 模型预标注与人工标签分离，保留原始证据 | **已完成 V1** |

代码层面的关键事实：

- `engine/python/basketball_engine/storage.py` 已支持 `pending / goal / excluded / deferred / second_review`、审核原因、审核耗时和旧库自动迁移。
- `list_candidates()` 仍按时间返回原始数据，审核 UI 在客户端按置信度、证据冲突和推荐分排序。
- `candidate_reviews` 与 `audit_events` 保存当前审核状态和每次审核历史；`evidence_json` 保留模型原始证据。
- `review_screen.dart` 已有候选区间时间轴、事件点、边界拖动、微调、循环播放和批量审核。

## 推荐的审核工作流

### 1. 分析完成后进入“审核收件箱”

顶部显示：

- `总候选`
- `待审核`
- `已确认`
- `已排除`
- `低置信度`
- `证据冲突`
- 当前进度，例如 `5 / 42`

默认排序不是简单按时间，而是：

1. 证据冲突且置信度低；
2. 模型判定与篮网/音频信号不一致；
3. 低置信度；
4. 普通候选按视频时间排序。

这样可以先处理最需要人工判断的样本，减少“从头看一遍视频”的感觉。

### 2. 三栏审核工作台

```text
左：候选队列       中：视频 + 候选时间轴       右：证据与操作
状态/优先级        事件点、区间、逐帧控制       模型分数、轨迹、篮网、音频
筛选/批量选择      播放、循环、拖动边界           确认、排除、原因、备注
```

审核者的主路径应该是：

1. 选中候选；
2. 自动跳到事件点并播放前后片段；
3. 必要时循环播放候选区间；
4. 查看证据摘要；
5. 点击 `确认进球`、`排除` 或 `暂缓`；
6. 排除时选择原因；
7. 自动进入下一个待审核候选。

### 3. 人工结果与模型结果分离

不要把“模型认为像进球”和“用户确认是进球”共用一个字段。建议逻辑模型为：

```text
candidate
  model_verdict       模型建议：goal / review / reject
  model_confidence    0.0 - 1.0
  evidence_json       原始证据
  review_status       pending / goal / excluded / deferred / second_review
  review_reason       pass / no_shot / pass_ball / rim_out / rebound / uncertain
  review_note         人工备注
  review_priority      数值或 low / normal / high
  reviewed_at         最近审核时间
  review_duration_ms  本次审核耗时
```

V1.5 的 UI 可以仍然只显示三类主按钮，但排除后必须选择原因；`deferred` 和 `second_review` 可以先作为内部状态或“暂缓”入口。

## 最值得直接吸收的交互

### 从 CVAT 吸收：状态与质量控制

- 候选不是一个按钮结果，而是一个有生命周期的审核对象。
- 支持“问题/疑点”标记，而不是只能确认或排除。
- 顶部显示实时审核进度。
- 为以后多人复核保留 `second_review`，但 V1 不实现账号和协作服务。

### 从 Label Studio 吸收：预标注与人工修正

- 保留模型原始判断，不被人工操作覆盖。
- 人工结果单独记录。
- 固定原因标签，避免备注内容无法统计。
- 导出训练数据时同时带上模型证据与人工标签。

### 从 FiftyOne 吸收：证据驱动筛选

- `低置信度`
- `模型与篮网信号冲突`
- `模型与音频信号冲突`
- `疑似传球`
- `疑似擦框/反弹`
- `没有投篮动作`

筛选结果应影响队列和批量操作，而不仅是改变一个下拉框。

### 从 LosslessCut 吸收：轻量时间线

第一版不做多轨剪辑，只做单轨候选时间线：

- 事件点竖线。
- 开始/结束两个可拖动手柄。
- 当前播放位置。
- `-1s / +1s` 微调。
- 逐帧前进/后退。
- 播放当前候选区间并自动停止。
- 片段重叠提示和合并提示。
- 快捷键与 Undo/Redo。

## 建议的实现优先级

### P0：审核工作流（已完成）

1. 增加固定原因枚举和 `deferred / second_review` 语义。
2. 审核队列支持状态、置信度、原因、证据冲突筛选。
3. 增加“按优先级审核”和“下一个待审核”。
4. 把 `evidence_json` 解析成右侧证据摘要。
5. 排除时强制选择原因，备注改为补充信息。
6. 顶部显示审核进度、确认率和剩余数量。

### P1/P2：已完成与后续边界

- 已完成：审核耗时统计、审核历史、批量操作失败保留、人工标签 JSONL/CSV 导出。
- 已完成：时间轴保存串行化，避免连续微调时后写入覆盖/丢失。
- 后续：训练数据批量抽样、跨视频评估报表和多人协作仍不纳入本地 V1。

### P1：提高单条审核效率

1. 把当前时间输入框升级为候选区间时间轴。
2. 支持拖动开始/结束边界。
3. 支持逐帧、循环播放、事件点跳转。
4. 支持多选候选和批量排除/确认/改原因。
5. 记录每条候选的审核开始时间、完成时间和耗时。

### P2：形成算法改进闭环

1. 审核历史表，不覆盖历史操作。
2. 导出 CSV/JSONL 训练样本。
3. 错误类型统计：传球、没投篮、擦框、反弹、网不动、真实进球等。
4. 按视频、机位、场馆和算法版本查看 Precision/Recall。
5. 用人工结果回灌阈值校准或时序分类器训练。

## 不建议现在做的事情

- 不引入 CVAT/Label Studio/FiftyOne 作为运行时依赖。
- 不做多人账号、权限、云端协作和共识投票。
- 不照搬 Kdenlive 的多轨、特效、转场和专业剪辑面板。
- 不在审核页重复运行模型；审核页只消费分析产物和缓存证据。
- 不把 UI 风格改动和审核数据模型混在同一个功能提交中，避免影响另一个 AI 正在进行的 UI 改版。

## 验收标准

审核 V1.5 达标的最低标准：

- 用户能在 3 次点击内从候选跳到可循环播放的片段。
- 用户能按“待审核/低置信度/疑似误报/证据冲突”筛选。
- 排除候选必须有可统计的原因。
- 确认/排除后自动进入下一个待审核候选。
- 片段边界可拖动并能逐帧微调。
- 页面能显示模型建议与人工最终结果的区别。
- 关闭并重新打开项目后，审核状态、原因、备注、区间和进度不丢失。
- 导出只使用人工确认的候选，并能看到导出片段数、总时长和处理耗时。

## 最终推荐

当前最优路线不是“做一个小型 Kdenlive”，也不是“嵌入 CVAT”，而是做一个**面向篮球进球候选的轻量审核工作台**：

> **FiftyOne 的筛选思路 + Label Studio 的结果分离 + CVAT 的审核状态 + LosslessCut 的时间线交互 + 现有篮球检测引擎的证据。**

先实现 P0，再实现 P1。这样能最大化复用现有代码，保持本地运行、低资源和后续移动端扩展能力。
