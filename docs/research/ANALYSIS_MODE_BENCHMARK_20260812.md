# 快速/标准模式基准记录（2026-08-12）

## 目的

在同一台 macOS Apple Silicon 机器、同一视频、同一模型和等比例 ROI 下，比较当前快速模式与标准模式的冷启动耗时。

## 输入与配置

| 项目 | 值 |
|---|---|
| 视频 | `data/videos/VID_20260804_165654.mp4` |
| 视频时长 | `277.656s` |
| 视频分辨率 | `1440×1080`、`30 FPS` |
| 模型 | 本地自备的 `models/bball_model.pt`（权重不随源码分发） |
| 源视频 ROI | `[585, 270, 840, 585]` |
| 标准代理 | `960×720 / 5 FPS`，代理 ROI `[390, 180, 560, 390]` |
| 快速代理 | `640×480 / 3 FPS`，代理 ROI `[260, 120, 373, 260]` |
| 粗扫 | `scale=4`、`batch=8`、`conf=0.10` |
| 标准精筛 | 原视频、`10 FPS`、`scale=2`、`window=2.5s` |
| 缓存 | 本次使用全新临时缓存目录，避免缓存命中影响冷启动对比 |

## 结果

| 模式 | 代理 | 粗扫 | 候选生成 | 精筛 | 合计 |
|---|---:|---:|---:|---:|---:|
| 标准 | `28.63s` | `25.66s` | `0.10s` | `21.34s` | **`75.73s`** |
| 快速 | `26.75s` | `15.22s` | `0.10s` | 跳过 | **`42.07s`** |

- 实测提速：`1 - 42.07 / 75.73 = 44.4%`。
- 两种模式的粗扫候选数均为 `15`；标准模式精筛后保留 `5 / 15` 个窗口。
- 该结果支持快速模式达到“相对标准模式提速至少 40%”的速度门槛。

## 结论边界

- 本次没有整段视频逐事件人工真值，因此**不能据此宣称快速模式召回率达到 80%～85%**。
- 当前桌面源码默认显示快速模式入口；可以通过 `--dart-define=ENABLE_FAST_ANALYSIS=false` 在构建时隐藏。无论入口是否显示，快速模式都必须继续提示可能漏检，不能把本次单样本速度结果当作准确率保证。
- 后续要开放快速模式，需要补充短、中、长视频的人工真值，比较关键片段召回率、候选时间重叠率和误报类型。

## 复现命令要点

使用 `scripts/create_proxy.py`、`scripts/scan_video.py`、`scripts/generate_candidates.py`；标准模式另执行 `scripts/refine_dynamic_candidates.py`。每次使用新的临时输出目录和缓存目录，分别记录 `/usr/bin/time -p` 的 `real` 时间。
