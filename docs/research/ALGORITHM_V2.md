# 篮球进球检测算法 V2

## 已吸收的开源思路

- `third_party/bball-highlights`
  - 球从篮筐上方到下方的几何穿越判定。
  - 上网区、下网区、篮下辅助区域。
  - 篮网信号只作为辅助，不作为唯一结论。
- `third_party/basketball-shot-detection`
  - 多球候选的距离关联。
  - 上方点到下方点的篮筐平面连线测试。
  - 球经过篮筐后不立即反弹的状态判断。
- `third_party/ai_basketball_games_video_editor`
  - 检测日志与剪辑流程分离。
  - 投篮事件前后窗口导出。

## V2 处理链

1. 代理视频低成本粗扫，生成候选时间点。
2. 回到原始视频，以 `30 FPS` 对候选窗口重新检测。
3. 同时检测 `ball` 与 `hoop`，在窗口内重新估计篮筐位置，适应 DJI 视频的轻微平移/变焦。
4. 使用两条球轨迹：
   - 连续轨迹关联：按速度预测和距离匹配，避免高置信度干扰球抢占轨迹。
   - 旧式最近高置信度轨迹：作为高召回 fallback，防止球被篮网遮挡时漏检。
5. 进球几何条件：
   - 球在篮筐上方出现。
   - 向下穿越篮筐平面。
   - 穿越点位于篮筐横向走廊。
   - 穿越后至少继续出现在篮下区域。
   - 检测到明显反弹或横向离开时拒绝。
6. 计算多信号评分：轨迹、速度、持续性、篮网分区运动、球检测置信度。
7. 使用当前 59 个人工审核片段做经验门控：
   - `high_precision`：自动导出。
   - `review`：进入人工审核队列。
   - `recall_review`：扩大召回的人工审核队列，不得直接自动导出。
   - `low`：不进入默认剪辑结果，但保留检测日志。

## 当前验证结果

针对已人工标注的 59 个候选片段，V2 全量输出：

- 原始精筛事件：64 个
- 去重后：59 个
- 默认审核队列：17 个
- 自动高置信度队列：16 个
- 高置信度队列中命中已标注进球：13 个

新增 `recall_review` 离线回放结果：

- 纳入人工审核：39 个
- 命中已确认进球：29 个
- 候选级 Precision：`74.4%`
- 候选级 Recall：`90.6%`
- 漏掉的已确认进球：`34、35、56`

该指标只代表当前机位和当前 59 个候选片段，不能直接泛化到其他场馆。

## 重要限制

当前机位为明显斜侧视角，擦框、擦网、从篮筐前后方穿过在二维画面中可能高度相似。算法应采用“高召回粗筛 + 高置信度自动导出 + 人工审核兜底”，不应承诺纯视觉 100% 判定。
