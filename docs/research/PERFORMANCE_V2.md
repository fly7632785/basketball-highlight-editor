# 性能优化 V2

## 已落地

- 粗扫支持批量 YOLO 推理：`--batch`，默认 8。
- 精筛支持批量 YOLO 推理：`--batch`，默认 8。
- 精筛支持按窗口缓存逐帧检测结果：`--cache-dir`。
- 新增 CFR 代理视频生成器：`scripts/create_proxy.py`。
- macOS 代理生成默认使用 `videotoolbox` 硬件解码/编码。

## 基准

基准文件：`data/artifacts/PERFORMANCE_BENCHMARK_V2.json`

在 60 秒测试片段上：

| 项目 | 耗时 |
|---|---:|
| 单帧推理 `batch=1` | 12.31 秒 |
| 批量推理 `batch=8` | 10.36 秒 |
| 代理生成（硬件） | 9.28 秒 |
| 代理扫描（`batch=8`） | 8.71 秒 |
| 精筛首次运行 | 4.99 秒 |
| 精筛缓存命中 | 1.45 秒 |

当前结论：批量推理在该小目标模型上只带来约 1.19 倍提升；**缓存是调参迭代的最大收益点**。代理链路需要在完整长视频上继续实测，但硬件解码已经明显优于纯 CPU 代理转码。

精筛解码复测：在同一批 21 个窗口上，将采样跳帧从 `read()` 改为 `grab()` + `retrieve()`，耗时从 `72.89` 秒降到 `68.78` 秒，约 `1.06×`；10 个精筛事件完全一致。

粗扫缓存复测：首次 60 秒扫描 `7.81` 秒，缓存命中 `1.37` 秒。缓存按视频/模型文件状态、ROI、采样率、缩放、batch 和置信度生成哈希，调候选门限时不再重复 YOLO 粗扫。

## 5 分钟真实长视频链路实测

测试视频：`dji_mimo_20260517_082410_0_1779109736239_video.mp4` 前 300 秒。

| 阶段 | 耗时 |
|---|---:|
| 代理生成（960×720、5 FPS、VideoToolbox） | 35.14 秒 |
| 代理粗扫（YOLO、batch=8） | 25.21 秒 |
| 原视频精筛（21 个候选、10 FPS） | 75.41 秒 |
| 代理粗扫 + 原视频精筛 | 135.76 秒 |

完整 62 分钟实际结果：代理生成 `455.91` 秒，代理粗扫 `292.75` 秒，原视频精筛 `457.74` 秒，合计 `1206.40` 秒（约 `20.11` 分钟）。相较当前 `2653.56` 秒（约 `44.23` 分钟）基线，耗时下降约 `54.5%`，速度约 `2.20×`。

注意：本次为了验证性能，使用了 `396 → 119` 的快速粗门控；与旧流程精筛事件仅有部分重合，因此**暂不把该门控作为正式默认参数**。正式版本需要加入独立运动触发并用完整标注验证召回率后再切换。

### 代理缩放复测

在同一份 62 分钟代理上复测：

| 参数 | 全片粗扫 | 粗候选数 |
|---|---:|---:|
| `scale=3` | 292.75 秒 | 396 |
| `scale=2` | 294.31 秒 | 390 |

`scale=2` 在 60 秒短测中更快，但全片没有实际提速，且少量候选发生变化。因此当前正式基线仍保留 `scale=3`，避免为了理论提速牺牲召回。

窗口合并实验：21 个窗口从 `68.78` 秒降到 `67.60` 秒，仅提速 `1.7%`，且篮网背景历史跨窗口导致 1 个候选变化，已回退，不作为默认路径。

## 下一步

3. 再评估合并相邻窗口和单次视频读取；只有在真实候选密度较高时才值得实现。
