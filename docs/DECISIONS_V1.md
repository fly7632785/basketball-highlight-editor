# 篮球集锦编辑器 V1 决策记录

> 本文件是当前产品、算法和工程方案的单一决策入口。历史研究文档保留原始结论；若与本文件冲突，以本文件的“当前决策”为准，并在这里追加变更原因。

## 当前决策

> 分析模式、性能记录、快速/标准模式边界和分期范围，详见 [`docs/research/ANALYSIS_MODES_V1.md`](research/ANALYSIS_MODES_V1.md)。该文档记录 2026-08-12 已确认的专项决策。

| 领域 | 当前决策 | 原因 |
|---|---|---|
| 产品入口 | macOS 桌面端先行，Windows 后续适配 | 先验证长视频本地闭环，减少跨平台同时建设的复杂度 |
| 移动端 | 后续做独立审核端，不阻塞桌面 MVP | 移动端主要承担审核，不把重型分析链提前塞进手机 |
| UI | Flutter + Material 3；使用 Riverpod 管理项目状态，go_router 管理四个桌面页面，media_kit 负责播放 | 已完成桌面 UI 重构，业务状态与页面路由已拆分 |
| 本地引擎 | V1 使用 Python 独立进程 | 复用已验证算法，避免现在承担 Rust/OpenCV 多平台编译成本 |
| 推理 | YOLO 篮球/篮筐检测 + 几何穿越 + 轨迹/篮网/音频辅助 | 吸收开源项目有效思路，不直接复制完整应用 |
| 视频处理 | FFmpeg 负责代理生成、精确取片和导出 | 代理用于审核，原始视频用于最终导出 |
| 数据 | SQLite 记录项目状态、审核状态、任务和导出统计 | 可恢复、可审计、离线可用 |
| 项目范围 | V1 单项目单视频单篮筐；Schema 预留多视频/多 ROI | 降低 UI 复杂度，同时避免后续推倒重来 |
| 原视频 | 只引用原路径，不复制、不移动、不自动删除 | 避免 8GB 级视频重复占用磁盘 |
| 审核 | 候选默认保留，用户剔除误检；漏检片段可从原视频当前时间段通过“补漏”加入候选后导出 | 单目固定机位无法保证擦框与进球 100% 可分，同时保留人工补录入口 |
| 任务 | 同时只运行一个重型分析任务；支持取消、发现中断任务并从头重试 | 控制内存和 GPU/MPS 资源；V1 不承诺任意帧断点续跑 |
| 默认片段 | 进球前 6 秒、后 3 秒，可在审核时调整 | 覆盖完整投篮动作并保留落地结果 |
| 导出 | MP4 / H.264 / AAC，硬件编码优先，软件回退；支持单独和合并导出 | 兼容性优先，保留平台优化空间 |
| 隐私 | 默认本地处理、不登录、不上传；未来匿名上传必须弹框授权 | 当前不依赖云端，保留算法改进的数据入口 |
| 主题 | 跟随系统、浅色、深色；中文优先，预留英文 | 桌面长时间使用需要可读性和可调整性 |
| 分析模式 | 首次默认标准；按项目记忆模式；快速模式使用独立 `640×480 / 3 FPS` 代理并跳过原视频精筛；标准模式完整分析 | 在允许少量漏检的前提下缩短长视频等待时间，同时保持审核和导出规则不变 |
| 分析结果切换 | 每次重新分析创建新批次，成功后原子切换；失败/取消保留当前结果 | 防止分析过程中审核区被半成品清空，保障用户已有结果 |
| 分析记录 | 按批次保存阶段耗时、缓存命中、设备和完整参数快照 | 能解释结果、验证提速效果并支持后续恢复 |
| 分析期间交互 | 保留旧候选，允许继续播放、审核和修改；分析完成前不允许导出 | 避免新批次启动时清空工作区，也避免候选替换与导出并发冲突 |
| 快速模式上线 | 先用功能开关隐藏，达到冷启动提速和召回率闸门后再开放 | 防止未经基准验证的降级参数直接影响用户结果 |

## 已吸收的开源思路

| 参考项目 | 吸收内容 | 当前实现边界 |
|---|---|---|
| `bball-highlights` | ROI、缓存、粗扫/精筛、候选审核、验证指标、几何穿越 | 重新实现为本项目的 Python 模块，不复制未授权代码 |
| `Basketball-Shot-Detection` | 球/筐检测、上方到下方轨迹、篮筐横向走廊、跳帧 | 适配固定机位和动态校准 |
| `AI_basketball_games_video_editor` | 检测日志与剪辑分离、投篮前后窗口、批处理结构 | 不采用其旧 YOLOv4/TensorRT 作为 V1 必选运行时 |
| `opencv-basketball-shot-tracker` | 事前轨迹预测、抛物线落点思想 | 作为辅助通道，不替代几何和人工审核 |
| `sports-highlight-detector` | 运动触发、片段合并、前后时间窗口 | 优先用于性能优化和候选去重 |
| `nbaction` | 篮筐附近降低阈值、动作上下文先验 | 作为后续实验，不阻塞桌面 MVP |

## 明确不作为 V1 前置的事项

- Rust 核心引擎、`ort`、ONNX Runtime 跨平台打包。
- iOS/Android 本地推理。
- 云端同步、账号系统、在线模型服务。
- 端到端时序分类器和大规模自有数据训练。
- 把 HSV 颜色识别作为主判定。

## 算法结论边界

- 当前算法目标是“高召回候选 + 人工审核”，不是无人值守自动剪辑。
- 30 分钟视频上的高 Precision 不能代表跨视频泛化；1 小时视频已证明固定绝对像素阈值会失效。
- 后续算法实验必须优先采用按篮筐宽度归一化、留一视频验证和错误类型分析。
- 任何新算法信号都必须保留原始证据字段，便于回放和撤销，不直接覆盖历史结果。

## 变更规则

任何改变以下内容的决定都要追加一条记录：

1. UI 与 Engine 的协议；
2. SQLite 业务状态模型；
3. 是否允许未审核候选进入导出；
4. 原始视频的复制、移动或上传策略；
5. 推理运行时和模型分发方式。
