# Courtside Stitch 功能逐页对照审查 V1

> 目的：把 Stitch 设计稿与 `docs/UX_FUNCTION_TRUTH_V1.md`、当前 Flutter 代码逐项对照，识别功能遗漏、文案偏差和 Stitch 自行新增的入口。
>
> 范围：只审查设计稿，不代表本轮要修改 Flutter UI。设计稿中的 HTML 是静态呈现，交互是否可用仍需回到现有代码和测试验证。

## 一、审查结论

### 结论等级

| 等级 | 含义 |
|---|---|
| P0 | 改设计前必须纠正，否则会改变产品入口或核心流程 |
| P1 | 设计稿遗漏现有功能，落地时会造成用户无法操作或误解 |
| P2 | 文案、状态、细节或可用性偏差，应在下一版设计稿补齐 |
| OK | 当前设计稿已表达，仍需实现时映射到现有组件 |

### 总体判断

- **P0：全局侧栏只展示展开态，没有收缩态；同时引入产品不存在的 `New session`。**
- **P0：Stitch 多处使用英文导航和英文状态（`Projects`、`Import`、`Review`、`Export`、`Engine: Ready`、`Completed`），不符合当前中文产品文案契约。**
- **P1：导入页添加了未定义的 `打开输出目录`、`Settings` 和顶部“快速/标准”导航，改变了四步向导的边界。**
- **P1：审核页桌面稿遗漏大量候选审核能力；窄窗稿遗漏候选工具、真实片段范围/时长、球员菜单和审核操作。**
- **P1：项目页将最近项目压缩成“项目名 + 最后修改时间”，遗漏视频名、保留数、候选数和视频时长。**
- **P1：导出页总体结构较接近，但没有明确 `返回审核`、中文导出阶段/状态、导出后可继续审核等关键语义。**
- **P2：静态稿存在示例数据和装饰入口，不能直接作为实现规格；必须以功能真相文档和当前运行代码为准。**

| 英文状态 | 中文产品状态 | 有 `Completed`、`Engine: Ready` | P0 | 全部改为中文状态 |
| New Session | 产品不存在 | 有 | P0 | 删除 |

## 九、修订优先级

### P0：先让 Stitch 停止改变产品

- 删除所有 `New session`、`Settings`、`Help`、`SORT`、导入页 `打开输出目录`；
- 所有导航、状态和按钮恢复中文；
- 补侧栏展开/收缩态及两个 Tooltip；
- 保持四页及窄窗底部导航，不加入额外页面。

### P1：补齐不能丢的业务能力

- Home 最近项目业务字段、加载/空/失败/工作流状态；
- Import 分析范围、ROI 操作、模式位置、弹框和状态；
- Review 候选真实范围/时长、状态筛选、批量、球员菜单、证据、补漏、空状态；
- Export 风险、阶段、冲突、返回审核、历史完整字段。

### P2：最后处理视觉细节

- 对齐、间距、密度、状态颜色、Tooltip 位置；
- 缩略图加载占位、进度过渡、菜单锚定和 reduced motion；
- 动效限制为 150–250ms，不能让候选行跳动或把控件移到视频中央。
