# 模型与数据授权边界

**结论先行：** 本项目源码采用 MIT，不代表模型权重、训练数据、输入视频、FFmpeg 或其他依赖可以按 MIT 分发。每一层都要单独核验。

## 需要分别确认的对象

1. 模型代码的许可证；
2. 模型权重的许可证和再分发条件；
3. 训练数据及衍生标注的公开处理权；
4. Ultralytics、PyTorch、OpenCV、ONNX Runtime、FFmpeg 等依赖的许可证；
5. 输入视频、球员画面、球队标识、场馆素材和导出片段的处理权限；
6. Android/iOS 原生库、静态链接物和平台 SDK 的分发条件。

“代码仓库是 MIT/Apache-2.0”不能推出“权重和数据也可以公开下载或商业分发”。没有权利证明时，只发布源码，要求使用者自行准备模型和视频。

## 本地模型约定

桌面 Engine 默认查找：

```text
models/bball_model.pt
```

移动端的 Flutter 资源和 ONNX/Rust Runtime 是独立的发布对象，应在打包前分别确认授权和 ABI 兼容性。模型缺失时，运行时检查应明确报告，不应静默从未知地址下载。

## 本地数据约定

真实比赛视频、球员图像、球队信息、人工标注和审核导出文件只用于本地验证，不应提交到公开仓库。即使视频来自公开平台，也需要确认下载、再处理和再分发权限。

## 公开发布前的证据

发布模型或二进制前，至少保留：

- 模型来源、版本、哈希和许可证文本；
- 训练数据来源及授权记录；
- Python/Flutter/FFmpeg/ONNX Runtime 版本和 notices；
- 演示视频、截图和标注的公开许可；
- 发布物中对应的第三方声明。

当前源码树检查结果和待处理项见 [`OPEN_SOURCE_AUDIT.md`](OPEN_SOURCE_AUDIT.md)。
