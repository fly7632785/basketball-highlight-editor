# V1 可执行路线图

## 当前目标

先完成“导入一个视频 → 配置篮筐 → 本地分析 → 审核候选 → 导出”的桌面闭环。算法模块沿用现有验证结果，不在此阶段继续扩大算法范围。

## 阶段顺序

### A. 工程基座（当前）

- [x] 沉淀架构、协议、Schema、设计系统和决策记录。
- [x] 创建可运行的 Flutter 桌面工程。
- [x] 创建 Python Engine JSONL 进程。
- [x] 验证 Engine 能初始化 SQLite 项目并读取视频元数据。
- [x] 通过 Engine 调用现有 `create_proxy.py` 生成可复用代理。
- [x] 保存 ROI、任务 checkpoint 和候选审核初始状态。

### B. 桌面 UI 骨架

- [x] 项目首页：新建项目入口和本地处理状态。
- [x] 已存在项目：手动选择项目目录并恢复视频、ROI、候选和统计上下文。
- [x] 首页最近项目：在显式配置的项目根目录内列出、刷新并直接打开项目。
- [x] 导入页：选择视频、展示时长/分辨率/编码、提取预览帧。
- [x] ROI 页：在预览帧上拖拽框选并保存篮筐区域。
- [x] 分析页：进度、阶段、取消和错误提示。
- [x] 审核页：内置视频播放器、时间轴、候选切换、片段播放、保留/排除、时间范围调整。
- [x] 导出页：单独导出、合并导出、导出统计。
- [x] 导出历史：记录输出路径、片段数、合计时长和处理耗时，并在导出页展示最近记录。

### C. Engine 闭环

- [x] `link_video` / `create_proxy` 接入真实视频。
- [x] `start_analysis` 调用现有粗扫/精筛脚本。
- [x] 候选结果写入 `candidates` 和 `candidate_reviews`。
- [x] `review_candidate` 与 `update_clip_range` 持久化审核结果。
- [x] `export_clips` 调用 FFmpeg，并写入导出统计。
- [x] 任务取消、阶段状态、日志和失败落库；发现中断任务并支持按 Manifest 复用已完成阶段。

### D. 验证与打包

- [x] 使用 5 分钟样本跑通 Engine 端到端流程。
- [x] 记录首次分析和导出耗时；30 分钟、1 小时样本作为性能回归数据集继续保留。
- [x] 内置时间轴播放器和候选片段预览。
- [x] 增加运行时检查和 macOS 运行时准备脚本，明确 Python/FFmpeg/模型打包边界。
- [ ] 在 macOS 完成可分发构建。
- [ ] 再评估 Windows 适配和 Python/FFmpeg 打包方式。

## 当前不需要用户决策

- Flutter 主题和页面骨架可以按已确认的深色工作台方向直接推进。
- Engine 先使用已有 Python 算法，不迁移 Rust。
- V1 数据库和协议按已确认文档落地。

## 需要用户决策时再暂停

- 选择正式应用名称和图标；
- 确认默认导出目录策略；
- 确认是否把“候选审核标签”纳入未来匿名上传授权；
- 决定 Windows 首个支持版本。
