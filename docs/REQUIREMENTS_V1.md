# 篮球集锦编辑器 V1 需求与状态

> 这是当前范围和验收状态，不是未来愿望清单。候选仍然必须人工审核，不能直接当成进球事实。

## 1. 产品边界

| 项目 | 当前定义 |
|---|---|
| 桌面端 | macOS 主路径；Windows 有兼容脚本但不是正式发布门槛 |
| 移动端 | 独立 Flutter App；Android 原生分析实验路径已接入，iOS 本地分析仍待 Runtime 链接 |
| 处理方式 | 默认本地处理，不上传原始视频，不需要账号 |
| 输入 | 单项目、单视频、单篮筐、固定机位 |
| 输出 | 未排除的候选片段，支持审核调整、手动补漏、分别导出和合并导出 |
| 算法定位 | 生成高召回疑似事件，用户审核后导出 |
| 默认片段 | 事件前 6 秒、事件后 3 秒；审核时可调整 |

## 2. 已实现的主流程

### 桌面端

- [x] 新建项目、选择视频、读取元数据。
- [x] 只保存原视频引用；源文件缺失时可重新定位。
- [x] 自动建议 ROI，失败时手动框选和调整。
- [x] 保存 ROI 后启动标准/快速分析。
- [x] 分析阶段、进度、耗时、取消、失败提示和重试。
- [x] 新分析期间保留旧候选，成功后再切换结果。
- [x] 应用重开后恢复项目、ROI、候选、审核结果和可恢复任务提示。
- [x] 审核工作台支持播放、暂停、进度拖动、候选切换、候选片段播放。
- [x] 候选支持保留/排除、备注、球员标签、时间范围调整和手动补漏。
- [x] 候选默认保留，只有排除候选不进入导出。
- [x] 支持分别导出、合并导出、进度、取消、失败重试和导出历史。
- [x] 导出记录文件路径、片段数、时长、耗时、文件大小和编码信息。
- [x] 重型任务前进行磁盘空间检查。

### 移动端

- [x] 独立 Flutter 工程、视频导入、元数据、项目持久化和项目包导入/导出。
- [x] ROI、分析范围、片段前后窗口和分析进度 UI。
- [x] Android 原生抽帧、取消、进度回传和平台视频片段导出。
- [x] Android Rust/ONNX Runtime channel；当前主要验证 `arm64-v8a`。
- [x] 移动端候选审核、备注、球员标签、导出和保存到媒体库入口。
- [x] 没有原生 Runtime 时明确返回 `NATIVE_RUNTIME_UNAVAILABLE`。
- [ ] iOS Rust 静态库、ONNX Runtime XCFramework 与 Runner 的完整链接。

## 4. 数据和任务要求

- 项目数据库位于项目目录内，可从最近项目列表恢复。
- 视频记录保存源路径、文件大小、修改时间和元数据；打开项目时重新验证源文件。
- ROI 保存归一化坐标和来源，区分自动建议与手动编辑。
- 候选保存事件时间、片段范围、审核状态、备注、标签和审核时间。
- 手动候选标记为 `manual-v1`，重新分析时不得静默丢失。
- 任务状态使用 `queued / running / completed / failed / cancelled`，保存错误码和错误信息。
- 取消、失败和重试不能删除已有项目数据和审核记录。
- 导出前重新读取当前审核状态；已排除候选不得导出，其他候选按当前产品决策默认保留。
- 合并导出按事件时间排序并处理重叠；桌面最终导出使用原视频。

## 5. 验收口径

### 功能验收

至少完成一次：

```text
新建 → 导入 → 元数据 → ROI → 标准分析 → 候选审核
→ 调整片段 → 分别导出/合并导出 → 重启恢复
```

同时验证：源视频移动后的重新定位、空候选排查、分析取消/重试和导出失败/重试。

### 性能与算法验收

每次修改分析参数都应记录：

- 视频时长、分辨率、编码和 ROI；
- 模式、代理规格、FPS、模型和算法版本；
- 各阶段耗时、缓存命中、候选数和设备；
- 人工真值、关键片段召回、误报类型和可重复性。

当前单样本性能记录只用于说明快速/标准的速度差异，不能替代多视频人工真值。见 [`benchmarks/ANALYSIS_MODE_BENCHMARK_20260812.md`](benchmarks/ANALYSIS_MODE_BENCHMARK_20260812.md)。
