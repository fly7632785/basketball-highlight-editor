# 篮球集锦编辑器 V1 需求与验收清单

> 本文件是 V1 功能范围的执行清单。实现状态以代码和本地验证结果为准；算法候选仍然必须人工审核，不能把候选直接当作进球事实。

## 1. 产品边界

| 项目 | V1 定义 |
|---|---|
| 平台 | macOS 桌面端；Windows 先保持架构兼容，不作为本轮发布门槛 |
| 处理方式 | 本地处理，不上传原始视频，不需要账号 |
| 输入 | 单项目、单视频、单篮筐、固定机位 |
| 输出 | 未排除的候选片段，包含人工确认和补漏片段，支持单独导出和合并导出 |
| 算法定位 | 高召回生成候选，用户审核后导出 |
| 默认片段 | 事件前 6 秒、事件后 3 秒；审核时可调整 |

## 3. 状态与数据要求

### 项目状态

- 项目数据库位于项目目录内，项目可从最近项目列表恢复。
- 视频记录必须保存源路径、文件大小、修改时间和元数据；打开项目时重新验证源文件。
- ROI 必须保存归一化坐标和校准来源，支持自动 ROI 与手动 ROI 区分。
- 候选必须保存事件时间、默认片段范围、当前审核状态、备注和审核时间。
- 手动候选标记为 `manual-v1`，重新分析时不得丢失。

### 任务状态

- UI 不能通过“等待中”代替真实状态，必须展示当前阶段和进度。
- 应用重开后只恢复数据库中仍有效的任务；运行线程不存在时标记为可恢复，而不能伪装成继续运行。
- 取消、失败、重试不能删除已有项目数据和审核记录。

### 导出规则

- 导出前重新读取当前审核状态，不信任 UI 缓存。
- 已排除候选不得导出；待审核候选按当前产品决策默认保留并进入导出。
- 补漏候选按普通候选处理，默认进入导出，用户可手动排除。
- 合并导出按事件时间排序，并避免重复重叠片段。
- 最终导出使用原始视频；代理视频只用于分析和审核预览。

## 5. 下一阶段执行顺序

1. 完成 macOS 可分发构建和干净环境安装验证。
2. 进行一次完整手测：新建 → 导入 → ROI → 分析 → 审核 → 导出 → 重开恢复。
3. 记录真实视频的分析耗时、导出耗时、内存和磁盘峰值。
4. 修复手测中发现的功能问题后，再冻结 V1 协议和数据库变更。
5. 冻结 V1 后再进入 Windows 适配和移动端审核端设计。

当前不再把历史研究中的实验计划视为 V1 任务；新的算法或性能工作必须新增带日期的验证记录，并把稳定结论同步到 `docs/DECISIONS_V1.md`。
