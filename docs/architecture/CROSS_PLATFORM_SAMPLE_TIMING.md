# 跨端采样时间契约

分析端统一使用**半开时间区间** `[start_ms, end_ms)`，第 `i` 个采样点定义为：

```text
sample_ms(i) = start_ms + round(i * 1000 / sample_fps)
```

其中 `sample_ms(i) < end_ms`。禁止通过 `floor(1000 / sample_fps)` 反复累加，因为这会在长视频中产生累计时间漂移。

各端职责：

- Python：根据采样时间换算第一个达到该时间的源帧索引，记录契约采样时间，而不是用解码循环的估计时间。
- Android：`MediaCodec` 顺序解码，只把第一个达到目标采样时间的帧交给 Runtime；Runtime 使用目标采样时间。
- iOS：`AVAssetReader` 顺序解码，只把第一个达到目标采样时间的帧交给 Runtime；Reader 不可用时才回退到 `AVAssetImageGenerator`。
- 代理视频：`time_offset` 只在 Python 粗扫输出时加回源时间轴，精筛和移动端直接使用源视频时间轴。

自动 ROI（篮筐区域建议）也使用同一套起点和时间网格：

- 起点是当前分析范围的 `start_ms`；
- 扫描窗口从起点开始最多 `20_000ms`，视频剩余时间不足时取剩余部分；
- 采样频率为 `1fps`，最多使用 `12` 个模型输入帧；
- Android/iOS 的 `durationMs` 由 Flutter 先截断到上述窗口，原生层再次限制到 `20_000ms`，避免旧调用方把整段长视频传入；
- 每帧最多保留前五个篮筐检测用于稳定聚类，达到五个检测后结束扫描。

因此，移动端自动 ROI 不会因为传入的是 30 分钟或 1 小时视频而扫描整段视频，也不会从被用户排除的片头重新取样。

这样做的目的是让 CFR 视频在三端选择同一源帧，并确保进入轨迹、篮网信号、窗口和事件判定的时间坐标一致且不随视频长度漂移。VFR 视频仍需以真实设备回放记录进一步验收。
