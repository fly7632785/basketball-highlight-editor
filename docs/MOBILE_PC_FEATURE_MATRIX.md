# BHE 桌面端与移动端功能差异矩阵

> 更新时间：2026-08-27
>
> 本文只记录当前代码中已经能找到的能力，不把规划中的功能写成已完成。状态以代码和现有文档为准，真机验收另行记录。

## 1. 状态说明

| 状态 | 含义 |
|---|---|
| `等价可用` | 两端都有对应能力，流程基本一致；仍需目标设备验收时标为“待验收” |
| `移动端部分` | 移动端有入口或简化实现，但能力/数据/错误恢复不等价 |
| `仅桌面端` | 桌面端已有，移动端没有对应实现 |
| `移动端待接入` | Flutter 页面或 channel 已存在，但原生库/真实设备链路尚未闭环 |
| `架构不一致` | 两端都有实现，但底层协议、数据结构或算法不同，不能视为同一能力 |

## 2. 主流程矩阵

| 功能域 | 桌面端 | 移动端 | 状态 | 差异 / 影响 |
|---|---|---|---|---|
| 新建项目 | 新建、选择视频、读取元数据 | 新建、选择视频、读取元数据 | `等价可用` | 移动端项目列表和删除流程较简化 |
| 最近项目 | 最近项目、打开、删除、关闭前任务处理 | 最近项目、打开、删除当前项目 | `移动端部分` | 没有桌面端完整的项目管理、任务关联和删除确认链路 |
| 源视频缺失 | 检测缺失、重新定位、重新校验 | 重新定位、时长/分辨率/抽样 SHA-256 校验 | `移动端部分` | 校验逻辑存在，但缺少完整的项目状态和失败恢复展示 |
| 项目包 | 桌面项目目录/数据库结构 | `.bhe` 压缩包，`format=bhe-project, version=1` | `架构不一致` | 两端项目包当前不能互相打开；不能在 PC/App 间无损接续 |
| 视频预览 | 预览帧、原视频、候选播放 | 原视频播放、候选时间段播放 | `移动端部分` | 移动端没有桌面端完整的预览帧/来源切换契约 |
| 分析范围 | 可预览并设置起止时间，保存 workflow draft | RangeSlider 设置起止时间 | `移动端部分` | 移动端缺少视频预览联动和草稿恢复 |
| ROI 自动建议 | 自动建议篮筐/篮网区域，返回来源、置信度、最佳帧，失败后手动调整 | 默认/手动拖动与四角缩放 | `仅桌面端` | 移动端没有接入桌面端自动建议及其置信度/最佳帧信息 |
| ROI 手动调整 | 篮筐、篮网分别调整，保存后用于分析 | 篮筐、篮网分别拖动和缩放 | `移动端部分` | 移动端已有基本编辑，但缺少桌面端校验、自动建议结果和引导信息 |
| 片段时长 | 默认前 6 秒 + 后 3 秒，可调候选范围 | 默认前 6 秒 + 后 3 秒，可调候选范围 | `等价可用` | 移动端只有 RangeSlider，拖动时没有桌面端同等即时预览 |
| 分析模式 | 标准/快速，展示模式风险和代理规格 | 标准/高质量，展示规格 | `移动端部分` | 命名和参数不是同一契约：桌面 `fast/standard`，移动端 `standard/highQuality` |
| 分析任务 | 阶段、进度、耗时、ETA、取消、失败、重试、恢复 | 阶段、进度、耗时、ETA、取消、失败、重新分析 | `移动端部分` | App 重启后只把 running 标为 interrupted，没有真正 checkpoint/resume |
| 空候选 | 空结果排查提示、重新分析入口 | 空结果提示、重新分析入口 | `移动端部分` | 移动端缺少候选层诊断信息和算法版本信息 |

## 3. 算法与结果矩阵

| 能力 | 桌面端 Python Engine | 移动端 Rust/ONNX Runtime | 状态 | 必须解决的问题 |
|---|---|---|---|---|
| 视频抽帧/代理 | 代理生成、粗扫、精筛、缓存、窗口合并 | Android 原生抽帧，Rust 接收检测数据 | `架构不一致` | 处理阶段和抽帧策略不同，性能及结果不能直接类比 |
| 模型推理 | 当前桌面模型和 Python 推理链 | ONNX Runtime Mobile，Android 主要验证 `arm64-v8a` | `移动端待接入` | 干净 clone 没有可复现的原生 `.so` 和 ONNX Runtime 依赖 |
| 模型产物 | `bball_model.pt` / 桌面依赖 | `bball_model.onnx`，仓库/发布策略需明确 | `架构不一致` | 必须做 Python vs ONNX 输出对比，并确认模型许可和分发方式 |
| 轨迹关联 | 多轨关联、连续扁平轨迹、恢复轨迹；门限相对篮筐宽度 | 基础多轨动态关联；按预测距离一对一匹配，并支持跨轨短遮挡拼接，最多 32 点 | `架构不一致` | 尚未迁移 Python 的全量精筛轨迹恢复和完整 recovery track 评分 |
| 轨迹预测 | 事前落点预测已接入候选评分和 review 路径 | 已实现 y(t) 二次 / x(t) 线性拟合与 R² 门槛，但坐标/候选时机不同 | `架构不一致` | 数学近似不代表实视频阈值等价 |
| 穿框判定 | above/below 深度、过渡走廊、穿框后连续点、反弹和横向离开等门控 | 已对齐 above/below 深度、过渡走廊和穿框后连续点；输入来自基础多轨及短遮挡拼接 | `架构不一致` | Python 的精筛输入和 recovery 评分仍未完全迁移，候选时间和完整穿框仍可能不同 |
| 篮网运动 | 背景、白网、橙色、方向、可用性和 baseline 等组合特征 | 三分区 8×8 灰度局部对比度帧差与同步运动抑制 | `架构不一致` | 同一视频两端的网运动分数没有可比性 |
| 反弹判断 | 完整 post-track、深度边界、横向离开和恢复分支 | 已实现近筐回升、横向离开和恢复语义；跨轨拼接策略仍较简化 | `架构不一致` | 输入轨迹不同仍会影响 missed 与 ambiguous 分布 |
| 候选评分 | `_score_crossing`、calibrated gates、预测融合、去重 | 已对齐 verdict 与核心 calibrated gates；保留 composite score 仅作移动端展示 | `架构不一致` | 两端置信度/排序仍不能按相同阈值比较 |
| 候选去重/合并 | 精筛后 `dedupe_candidates`，默认 2 秒 | 事件时间 2 秒内去重 | `部分对齐` | Rust 仍未迁移 Python 的窗口级候选合并 |
| 算法版本 | `python-v2.14-white-net-trajectory` 写入 job / detector / export | Candidate 已写入 `analysis-contract-v1`；Runtime 仍公开 `bhe_runtime/0.1.0` | `移动端部分` | 需要把 contract version 写入移动端 job / 项目包 |
| 轨迹可视化数据 | 轨迹、穿框、预测、signals、gates、verification | 轨迹、穿框、基础分数、reason/verdict | `移动端部分` | Rust 尚未输出完整的 net / gate / verification 证据 |

**结论：当前移动端不是桌面端算法的等价迁移。** 后续变更遵循 [`CROSS_PLATFORM_ANALYSIS_CONTRACT_V1.md`](architecture/CROSS_PLATFORM_ANALYSIS_CONTRACT_V1.md)；在已有 5 分钟、30 分钟、1 小时样本上完成跨端回放前，不应宣称“App 与 PC 结果一致”。

## 4. 审核矩阵

| 能力 | 桌面端 | 移动端 | 状态 | 说明 |
|---|---|---|---|---|
| 候选按时间排序 | 支持 | 支持 | `等价可用` | 移动端通过上下滑动切换 |
| 保留/排除 | 支持 | 支持 | `等价可用` | 移动端支持全部保留/全部排除 |
| 播放控制 | 播放、暂停、重播、循环、倍速、快进/快退 | 播放、暂停、重播、倍速、快进/快退 | `移动端部分` | 移动端没有桌面键盘快捷键，但需要完整触摸等价交互 |
| 候选片段播放 | 支持候选窗口和原视频切换 | 基于原视频 seek 到候选窗口 | `移动端部分` | 还没有独立候选代理/无缝预加载策略 |
| 片段范围调整 | 支持候选时间范围调整 | 支持 RangeSlider | `移动端部分` | 缺少拖动时即时预览、边界提示和保存历史 |
| 备注 | 支持 | 支持 | `等价可用` | 需要补充移动端展示和持久化回归测试 |
| 球员标签 | 新建、删除、单个设置、批量设置 | 新建/添加、单个设置 | `移动端部分` | 缺少删除球员和批量设置 |
| 候选批量操作 | 批量保留/排除、批量标签 | 全部保留/全部排除 | `移动端部分` | 缺少多选候选和批量标签 |
| 手动补漏 | 支持创建手动候选 | 无 | `仅桌面端` | 移动端无法把漏检事件加入审核队列 |
| 审核撤销 | 支持 review history 和 undo | 无 | `仅桌面端` | 移动端误操作不可恢复 |
| 证据详情 | 置信度、轨迹、穿框、篮网、反弹、预测、reason/verdict | 仅少量分数 | `仅桌面端` | 这是当前 App 审核可信度和可解释性的主要缺口 |
| 标注开关 | 轨迹线、点、穿框和证据叠加开关 | 无 | `仅桌面端` | 移动端当前只能看视频和列表 |
| 候选筛选 | 全部、保留、排除、状态/原因等 | 全部、保留、排除 | `移动端部分` | 缺少 reason/verdict/球员组合筛选 |

## 5. 导出矩阵

| 能力 | 桌面端 | 移动端 | 状态 | 影响 |
|---|---|---|---|---|
| 分别导出 | 支持 | 支持 | `等价可用` | 移动端逐个导出，长列表耗时更长 |
| 合并导出 | 支持 | 无 | `仅桌面端` | 移动端不能直接生成一条完整集锦 |
| 按球员导出 | 支持 | 支持 | `移动端部分` | 移动端是简单字符串过滤，没有桌面端 player id 契约 |
| 未分配球员 | 支持 | 无独立筛选 | `仅桌面端` | 无法只导出未标记片段 |
| 当前候选导出 | 支持 | 支持 | `等价可用` | 需确认移动端边界和音频兼容性 |
| 相册/文件/分享 | 文件、分享等桌面能力 | 相册、文件/系统分享入口 | `移动端部分` | 目标系统权限和失败提示需真机验证 |
| 进度/取消 | 进度、取消、失败、重试 | 有进度，取消/重试不完整 | `移动端部分` | 移动端没有完整导出 job、历史和恢复契约 |
| 导出历史 | 有耗时、文件大小、编码、片段数等记录 | 无 | `仅桌面端` | 用户无法查看上次导出结果和失败原因 |
| 输出统计 | 片段数、时长、耗时、文件信息 | 部分显示 | `移动端部分` | 需要统一统计字段和项目包格式 |

## 6. 数据模型与持久化差异

### 移动端当前已保存

- 视频路径、名称、大小、时长、分辨率、抽样 SHA-256；
- 篮筐 ROI、篮网 ROI；
- 分析范围、分析模式、片段前后时长；
- 候选时间范围、选择状态、置信度、三个基础分数；
- 备注、球员字符串标签；
- 最近一次分析耗时、时间、状态、进度、消息；
- 最近一次导出耗时。

### 移动端缺失的桌面数据

- 项目/视频/算法版本；
- 分析 job、checkpoint、各阶段耗时、缓存命中和错误码；
- ROI 自动建议来源、置信度、最佳帧和失败原因；
- 候选 detector version、完整 evidence、手动来源标记；移动端已保存基础 reason/verdict/overlay 字段；
- 审核历史、审核时间、撤销链；
- 导出 job、导出历史、输出路径、文件大小、编码和失败原因；
- 项目 schema 版本和迁移策略。

## 7. 发布阻塞项

### P0：不解决就不能称为“移动端完整流程”

1. Android 干净构建无法取得 `libbhe_runtime.so`、`libonnxruntime.so` 和模型的可复现输入。
2. iOS Rust 静态库、ONNX Runtime XCFramework 尚未完整链接 Runner。
3. 移动端算法与 PC 算法不等价，至少要完成统一候选 schema 和跨端样本对比。
4. 分析任务没有真正 checkpoint/resume，长视频中断后只能重新分析。
5. 移动端证据字段已经接入基础轨迹/穿框/原因，但还没有覆盖桌面端的完整 reason/verdict 和预测/反弹数据。

### P1：不解决就不能称为“审核效率与桌面端接近”

1. 补齐标注叠加和证据详情与桌面端的字段一致性；
2. 手动补漏、审核撤销；
3. 多选候选和批量球员标签；
4. 合并导出、导出取消/重试、导出历史；
5. 统一 PC/App 项目包或明确只支持单端项目包。

### P2：体验增强

1. 移动端分步新建项目流程；
2. 视频预览联动分析范围和候选范围；
3. 大文件、耗时、电量、存储空间预估；
4. 项目统计、任务恢复入口和更完整的最近项目管理。

## 8. 建议实施顺序

| 阶段 | 目标 | 交付物 | 验收门槛 |
|---|---|---|---|
| M0 | 锁定跨端契约 | 统一 `Candidate` evidence/reason/verdict、算法版本、分析/导出 job 字段 | Dart/Rust/桌面 JSON 能互转，旧项目可读取 |
| M1 | Android 可复现 | 固定 NDK/ORT/模型输入，补齐 ABI 构建说明和 CI 检查 | 干净 clone 可构建，真机能完成分析并返回候选 |
| M2 | 算法接近 PC | Rust 迁移轨迹关联、穿框、预测、篮网、反弹、去重 | 5 分钟、30 分钟、1 小时对比报告有明确差异阈值 |
| M3 | App 可审核 | 证据 overlay、原因详情、补漏、撤销、批量标签 | 不看 PC 也能完成候选审核 |
| M4 | App 可交付 | 合并导出、导出 job/历史/重试、项目恢复 | 选中候选可生成可播放的集锦并恢复状态 |
| M5 | iOS 闭环 | XCFramework、Runner 链接、真机分析 | iOS 16+ 完成同一验收脚本 |

## 9. 本轮结论

- **当前 App 已经是可运行的 Flutter 原型，不是桌面端的完整移动版。**
- **最大缺口不是页面数量，而是移动 Runtime、算法结果、证据数据和项目任务模型没有与 PC 统一。**
- 下一轮不先继续扩展 UI；先做 M0：统一结果/任务/项目包契约，再做 Android 可复现构建和跨端样本对比。
